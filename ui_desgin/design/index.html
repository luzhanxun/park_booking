04 · 动效

只做“状态可感知”的过渡：页面切换、弹层、选中反馈。系统开启“减弱动态效果”时，全部降级为淡入淡出或直接呈现。

令牌时长使用场景
--dur-fast140ms按钮、营位、标签的 hover / 按下
--dur-base200ms页面左右切换、抽屉、Toast
--dur-slow320ms底部弹层升起、地图选位面板
--dur-slower480ms核销结果、支付结果的出现动画
--ease-smoothcubic-bezier(.22,1,.36,1)默认缓动，不回落、不弹跳
--ease-standardcubic-bezier(.2,.8,.25,1)颜色与透明度过渡

为什么不用回弹曲线

回弹（overshoot）会让“核销成功 / 支付成功”这类结果页显得轻佻，也容易在低端安卓机上掉帧。 本项目统一使用“快速启动、长尾收敛”的缓动，保证操作反馈明确但不喧闹。

06 · 双端布局原则

两端共享令牌与组件，但信息密度、导航方式和主操作位置完全不同，不做“同一套模板换皮”。

小程序 · 单列、拇指优先

  • 一屏只做一件事：选公园 → 选日期时段 → 选营位 → 确认下单。
  • 主按钮固定在底部拇指区，高度 ≥ 48px，避让安全区。
  • 地图是选位主视图，列表作为等价入口与失败回退。
  • 仅保留“首页 / 预约 / 我的”三个底部标签。
  • 卡片圆角 14px、奶油底色，弱化边框，用留白分组。

后台 · 侧栏、表格优先

  • 深森林侧栏固定 248px，顶部栏 64px 放面包屑与全局搜索。
  • 列表页统一“筛选栏 + 批量操作 + 表格 + 分页”结构。
  • 危险操作（关闭营位、驳回、退款）二次确认并说明影响。
  • 状态用标签而非整行染色，保证长表格可扫读。
  • 编辑与审批分权，地图发布前对小程序不可见。

07 · 验收口径

以下 8 条同时适用于原型评审与后续开发验收，可直接作为测试用例的标题。

  1. 触控目标 ≥ 44 × 44px

    小程序所有可点区域（含地图营位、加减号、关闭按钮）满足最小触控尺寸，底部主按钮避让安全区。

  2. 状态三重表达

    颜色 + 图标 + 文字同时出现；灰度打印或色觉障碍用户仍能分辨可预约、剩余少量、已约满、维护中。

  3. 正文对比度 ≥ 4.5:1

    浅色底上的状态文字使用 700 级令牌；辅助灰仅用于占位与非关键信息，不承载业务结论。

  4. 一单一日期一时段一营位

    界面不提供多日、多营位、包场入口；整日场与分时场互斥，切换时清空已选营位并提示。

  5. 地图失败可回退

    平面图加载失败或数据缺失时，自动切换为列表选位，保留已选公园、日期与时段，不要求用户重来。

  6. 不可约状态不可下单

    临时关闭、维护中、已约满的营位不可选中；已选后状态变化，进入确认页前二次校验并阻断。

  7. 编辑与审批分离

    地图草稿 → 提交 → 审批 → 发布全链路留痕；审批人不得为同一张图的编辑人，驳回必须填写原因。

  8. 核销四重校验

    待使用状态、所属公园、未被核销、未过期；任一不满足即失败，并给出明确原因与下一步指引。
